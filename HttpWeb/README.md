# HTTP Запрос — Документация

## Описание

Активность **HTTP Запрос** предназначена для выполнения HTTP-запросов к внешним API и веб-сервисам. Поддерживает все основные HTTP-методы, настройку заголовков, тела запроса, таймаутов и клиентских сертификатов для аутентификации.

---

## Основные возможности

- ✅ Поддержка методов: GET, POST, PUT, DELETE, PATCH
- ✅ Настройка произвольных HTTP-заголовков
- ✅ Отправка тела запроса (JSON, XML, plain text)
- ✅ Настраиваемый таймаут запроса
- ✅ Клиентская аутентификация через сертификаты (.pfx)
- ✅ Опциональное игнорирование SSL-ошибок (для тестовых сред)
- ✅ Получение кода ответа, тела и заголовков

---

## Параметры активности

### 1. Основные параметры

#### URL (обязательный)
- **Тип:** `string`
- **Описание:** Адрес запроса (полный URL с протоколом)
- **Примеры:**
  ```csharp
  "https://api.example.com/users"
  "http://localhost:8080/api/v1/data"
  "https://jsonplaceholder.typicode.com/posts/1"
  ```

#### Метод
- **Тип:** `HttpMethodType` (enum)
- **Значения:** GET, POST, PUT, DELETE, PATCH
- **По умолчанию:** GET
- **Описание:** HTTP-метод запроса

#### Заголовки (JSON)
- **Тип:** `string` (JSON)
- **По умолчанию:** `{}`
- **Описание:** Словарь заголовков запроса в формате JSON
- **Примеры:**
  ```json
  {
    "Content-Type": "application/json",
    "Authorization": "Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "Accept": "application/json",
    "X-API-Key": "your-api-key-here"
  }
  ```

#### Тело запроса
- **Тип:** `string`
- **Описание:** Тело запроса (используется для POST, PUT, PATCH)
- **Примеры:**
  ```json
  // JSON
  {"name": "John Doe", "email": "john@example.com", "age": 30}
  
  // XML
  <user><name>John Doe</name><email>john@example.com</email></user>
  
  // Plain text
  Simple text data
  ```

#### Таймаут (сек)
- **Тип:** `int`
- **По умолчанию:** 100
- **Описание:** Время ожидания ответа от сервера в секундах
- **Примеры:** `30`, `60`, `120`

---

### 2. Сертификаты и SSL

#### Использовать сертификат
- **Тип:** `bool`
- **По умолчанию:** `false`
- **Описание:** Включает использование клиентского сертификата для аутентификации

#### Путь к сертификату
- **Тип:** `string` (путь к файлу)
- **Описание:** Путь к файлу клиентского сертификата (.pfx)
- **Пример:** `"C:\Certificates\client.pfx"`
- **Обязательно:** Если включен флаг "Использовать сертификат"

#### Пароль сертификата
- **Тип:** `string`
- **Описание:** Пароль для расшифровки файла .pfx
- **Пример:** `"MySecurePassword123"`

#### Игнорировать ошибки SSL
- **Тип:** `bool`
- **По умолчанию:** `false`
- **Описание:** Игнорирует ошибки проверки SSL-сертификата сервера
- **⚠️ ВНИМАНИЕ:** Используйте только в тестовых средах! В продакшене это создаёт угрозу безопасности.

---

### 3. Выходные параметры

#### Код ответа
- **Тип:** `int`
- **Описание:** HTTP status code ответа сервера
- **Примеры:**
  - `200` — OK (успешный запрос)
  - `201` — Created (ресурс создан)
  - `400` — Bad Request (некорректный запрос)
  - `401` — Unauthorized (требуется аутентификация)
  - `404` — Not Found (ресурс не найден)
  - `500` — Internal Server Error (ошибка сервера)

#### Тело ответа
- **Тип:** `string`
- **Описание:** Содержимое ответа сервера (JSON, XML, HTML, plain text)
- **Пример:**
  ```json
  {
    "id": 1,
    "name": "John Doe",
    "email": "john@example.com"
  }
  ```

#### Заголовки ответа (JSON)
- **Тип:** `string` (JSON)
- **Описание:** Заголовки ответа сервера в формате JSON
- **Пример:**
  ```json
  {
    "Content-Type": "application/json; charset=utf-8",
    "Server": "nginx/1.18.0",
    "X-Request-Id": "abc123",
    "Date": "Mon, 15 Feb 2025 10:30:00 GMT"
  }
  ```

## Обработка ошибок

### Типичные ошибки и их решения

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `URL не может быть пустым` | Не указан URL | Укажите корректный URL с протоколом http/https |
| `Файл сертификата не найден` | Неверный путь к .pfx | Проверьте путь к файлу сертификата |
| `Таймаут запроса` | Сервер не отвечает | Увеличьте таймаут или проверьте доступность сервера |
| `401 Unauthorized` | Неверная аутентификация | Проверьте токен/ключ API в заголовках |
| `404 Not Found` | Ресурс не найден | Проверьте корректность URL |
| `500 Internal Server Error` | Ошибка на стороне сервера | Проверьте логи сервера или обратитесь к администратору |

### Проверка успешности запроса

```csharp
// После выполнения активности HTTP Запрос
if (statusCode >= 200 && statusCode < 300)
{
    // Успешный запрос
    Console.WriteLine("Запрос выполнен успешно");
}
else if (statusCode >= 400 && statusCode < 500)
{
    // Ошибка клиента
    Console.WriteLine("Ошибка в запросе: " + statusCode);
}
else if (statusCode >= 500)
{
    // Ошибка сервера
    Console.WriteLine("Ошибка сервера: " + statusCode);
}
```

## Рекомендации по безопасности

### ✅ Рекомендуется

1. **Используйте HTTPS** вместо HTTP для защиты данных
2. **Храните токены и ключи API** в защищённых переменных или конфигурационных файлах
3. **Валидируйте SSL-сертификаты** в продакшен-среде (не включайте "Игнорировать ошибки SSL")
4. **Используйте таймауты** для предотвращения зависания процесса
5. **Логируйте коды ответов** для отладки и мониторинга

### ❌ Не рекомендуется

1. **Не храните пароли и токены** в открытом виде в коде
2. **Не игнорируйте SSL-ошибки** в продакшене
3. **Не используйте слишком большие таймауты** (может привести к зависанию)
4. **Не отправляйте чувствительные данные** через HTTP (только HTTPS)

## Часто задаваемые вопросы (FAQ)

### Как передать массив в JSON?

```json
{
  "users": [
    {"name": "John", "age": 30},
    {"name": "Jane", "age": 25}
  ]
}
```

### Как работать с pagination?

```csharp
// Первая страница
URL: "https://api.example.com/users?page=1&limit=10"

// Вторая страница
URL: "https://api.example.com/users?page=2&limit=10"
```

### Как отправить form-data?

Измените заголовок Content-Type:
```json
{"Content-Type": "application/x-www-form-urlencoded"}
```

Тело запроса:
```
name=John&email=john@example.com&age=30
```

### Как обработать ответ с ошибкой?

```csharp
// Проверяем код ответа
if (statusCode != 200)
{
    // Парсим тело ответа с описанием ошибки
    var errorMessage = responseBody;
    throw new Exception($"API Error {statusCode}: {errorMessage}");
}
```

## Производительность

### Рекомендации по оптимизации

1. **Используйте разумные таймауты** (30-60 секунд для большинства API)
2. **Переиспользуйте соединения** — активность автоматически управляет HttpClient
3. **Кэшируйте токены** — не запрашивайте новый токен при каждом запросе
4. **Используйте асинхронные запросы** — активность работает асинхронно

### Типичное время выполнения

| Тип запроса | Среднее время |
|-------------|---------------|
| GET (локальный API) | 10-50 мс |
| GET (внешний API) | 100-500 мс |
| POST с небольшим телом | 100-300 мс |
| POST с большим телом | 500-2000 мс |
