# Активность "Логирование сообщения" (LogMessageBack)

## Описание

Активность предназначена для централизованного логирования сообщений в процессе RPA.
Позволяет записывать сообщения в файл, в лог Primo или одновременно в оба источника с поддержкой уровней логирования, форматирования и автоматической ротации файлов.

Активность подходит для production-процессов, аудита действий, диагностики ошибок и построения единой системы логирования.

---

## Основные возможности

* ✅ Поддержка уровней логирования (Debug, Info, Warning, Error, Critical)
* ✅ Вывод в файл, в лог Primo или в оба источника
* ✅ Автоматическая ротация лог-файлов
* ✅ Гибкий шаблон формирования имени файла
* ✅ Настраиваемый формат сообщения
* ✅ Автоматическое создание директории логов
* ✅ Потокобезопасная запись в файл
* ✅ Возврат фактического пути записанного файла

---

## Входные параметры

### Основные параметры

| Параметр                | Тип             | По умолчанию     | Описание                        |
| ----------------------- | --------------- | ---------------- | ------------------------------- |
| **Сообщение***          | `string`        | -                | Текст сообщения для логирования |
| **Уровень логирования** | `LogLevel`      | `Info`           | Уровень важности сообщения      |
| **Режим вывода**        | `LogOutputMode` | `FileAndConsole` | Куда выводить сообщение         |

### Уровни логирования (LogLevel)

| Значение   | Описание                 |
| ---------- | ------------------------ |
| `Debug`    | Отладочная информация    |
| `Info`     | Информационное сообщение |
| `Warning`  | Предупреждение           |
| `Error`    | Ошибка                   |
| `Critical` | Критическая ошибка       |

---

### Режим вывода (LogOutputMode)

| Значение         | Поведение                      |
| ---------------- | ------------------------------ |
| `FileOnly`       | Запись только в файл           |
| `ConsoleOnly`    | Запись только в лог Primo      |
| `FileAndConsole` | Запись и в файл, и в лог Primo |

---

## Настройки файла (используются при выводе в файл)

| Параметр                     | Тип                   | По умолчанию | Описание                            |
| ---------------------------- | --------------------- | ------------ | ----------------------------------- |
| **Директория логов***        | `string`              | -            | Путь к папке хранения логов         |
| **Базовое имя файла**        | `string`              | `"log"`      | Имя файла без расширения            |
| **Расширение файла**         | `string`              | `".log"`     | Расширение файла                    |
| **Шаблон имени файла**       | `LogFileNameTemplate` | `WithDate`   | Способ формирования имени           |
| **Пользовательский шаблон**  | `string`              | -            | Используется при выборе Custom      |
| **Стратегия ротации**        | `LogRotationStrategy` | `Daily`      | Правило создания новых файлов       |
| **Максимальный размер (МБ)** | `int`                 | `10`         | Используется при ротации по размеру |

**Примечание:** Параметры со звездочкой (*) обязательны при записи в файл.

---

## Выходные параметры

| Параметр                      | Тип      | Описание                                     |
| ----------------------------- | -------- | -------------------------------------------- |
| **Путь к файлу лога**         | `string` | Фактический путь, в который выполнена запись |
| **Форматированное сообщение** | `string` | Итоговое сообщение после форматирования      |

## Примеры использования

### Пример 1: Простое информационное сообщение

```
Входные параметры:
- Сообщение: "Процесс успешно завершен"
- Уровень логирования: Info
- Режим вывода: ConsoleOnly

Результат:
Сообщение выводится в лог Primo
```

---

### Пример 2: Запись в файл с датой в имени

```
Входные параметры:
- Сообщение: "Начало обработки файла"
- Уровень логирования: Debug
- Режим вывода: FileOnly
- Директория логов: "C:\Logs"
- Базовое имя файла: "process"
- Шаблон имени файла: WithDate

Результат:
C:\Logs\process_2026-02-16.log
```

---

### Пример 3: Критическая ошибка с выводом в файл и лог

```
Входные параметры:
- Сообщение: "Не удалось подключиться к серверу"
- Уровень логирования: Critical
- Режим вывода: FileAndConsole
- Директория логов: "C:\Logs"
- Стратегия ротации: Daily

Описание:
Сообщение записывается в файл текущего дня и одновременно выводится в лог Primo
```

---

### Пример 4: Ротация по размеру файла

```
Входные параметры:
- Сообщение: "Промежуточный результат"
- Режим вывода: FileOnly
- Стратегия ротации: BySize
- Максимальный размер: 5 МБ

Описание:
При превышении 5 МБ создается новый файл:
log_2026-02-16_0001.log
log_2026-02-16_0002.log
```

## Шаблоны имени файла

### 1. Fixed

```
log.log
```

### 2. WithDate

```
log_2026-02-16.log
```

### 3. WithDateTime

```
log_2026-02-16_14-30.log
```

### 4. WithTimestamp

```
log_20260216143055.log
```

### 5. Custom

Поддерживаемые плейсхолдеры:

| Плейсхолдер            | Значение            |
| ---------------------- | ------------------- |
| `{base}`               | Базовое имя         |
| `{ext}`                | Расширение          |
| `{date}`               | yyyy-MM-dd          |
| `{time}`               | HH-mm-ss            |
| `{timestamp}`          | yyyyMMddHHmmss      |
| `{level}`              | Уровень логирования |
| `{guid}`               | GUID                |
| `{yyyy}` `{MM}` `{dd}` | Части даты          |
| `{HH}` `{mm}` `{ss}`   | Части времени       |

Пример:

```
{base}_{yyyy}-{MM}-{dd}_{HH}-{mm}{ext}
```

---

## Стратегии ротации

### None

Один файл без ограничений.

### Daily

Новый файл создается каждый день.

### Hourly

Новый файл создается каждый час.

### BySize

Новый файл создается при превышении заданного размера.

## Форматирование сообщения

| Параметр                 | Назначение                    |
| ------------------------ | ----------------------------- |
| Добавлять время          | Вставка timestamp             |
| Добавлять уровень        | Вставка уровня                |
| Формат времени           | Настраиваемый формат DateTime |
| Добавлять перенос строки | Автоматический перевод строки |

Формат по умолчанию:

```
[2026-02-16 14:30:15.123] [INFO    ] Сообщение
```

## Алгоритм работы

```
1. Получение и валидация параметров
   ├─ Проверка обязательных значений
   ├─ Проверка директории
   └─ Проверка стратегии ротации
   ↓
2. Формирование имени файла
   ├─ Применение шаблона
   └─ Учет стратегии ротации
   ↓
3. Форматирование сообщения
   ├─ Добавление времени
   ├─ Добавление уровня
   └─ Добавление переноса строки
   ↓
4. Запись сообщения
   ├─ В файл (при необходимости)
   └─ В лог Primo (при необходимости)
   ↓
5. Установка выходных параметров
   └─ Возврат результата
```

## Обработка ошибок

| Ошибка                    | Причина                 | Решение                           |
| ------------------------- | ----------------------- | --------------------------------- |
| Директория не существует  | Неверный путь           | Проверить путь                    |
| Нет доступа к файлу       | Недостаточно прав       | Запустить от имени администратора |
| Некорректный шаблон имени | Ошибка в Custom шаблоне | Проверить плейсхолдеры            |
| Размер файла не задан     | При выборе BySize       | Указать размер                    |

## Производительность и особенности

* Запись выполняется синхронно
* Используется `lock` для потокобезопасности
* Директория создается автоматически при отсутствии
* Сообщения добавляются в конец файла
* Сортировка или чтение файлов не выполняется

## Технические детали

### Зависимости

* .NET Framework
* System.IO
* System.Text
* System.Threading

### Архитектура

**Основные компоненты:**

* `LogLevel` — перечисление уровней
* `LogOutputMode` — режим вывода
* `LogRotationStrategy` — стратегия ротации
* `LogFileNameTemplate` — шаблон имени

### Потоки выполнения

* Синхронное выполнение
* Без создания дополнительных потоков
* Потокобезопасная запись через статический `lock`

---

## Ограничения

* Максимальная длина пути — 260 символов (ограничение Windows)
* Ротация по размеру требует указания лимита
* Custom шаблон должен содержать `{base}` или фиксированное имя
