# Активность "Поиск файлов" (SearchFilesBack)

## Описание

Активность предназначена для поиска файлов и папок в указанной директории с поддержкой различных типов фильтрации и рекурсивного поиска. Поддерживает как простые wildcard маски, так и сложные regex паттерны.

## Основные возможности

- ✅ Поиск файлов, папок или обоих типов одновременно
- ✅ Поддержка **wildcard** масок (`*.txt`, `file_?.csv`)
- ✅ Поддержка **regex** паттернов для сложной фильтрации
- ✅ Рекурсивный поиск в подпапках
- ✅ Защита от зависания с настраиваемым таймаутом
- ✅ Возврат отсортированного списка найденных элементов
- ✅ Счетчик найденных элементов

## Входные параметры

### Основные параметры

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| **Путь к директории*** | `string` | - | Полный путь к директории для поиска<br>Пример: `"C:\Documents"` |
| **Тип фильтрации** | `SearchFilterType` | `Wildcard` | Способ фильтрации файлов:<br>• `Wildcard` - использование `*` и `?`<br>• `Regex` - регулярные выражения |
| **Паттерн поиска*** | `string` | `"*"` | Маска или паттерн для фильтрации<br>Зависит от выбранного типа фильтрации |

### Настройки поиска

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| **Что искать** | `SearchType` | `FilesOnly` | Тип искомых элементов:<br>• `FilesOnly` - только файлы<br>• `FoldersOnly` - только папки<br>• `FilesAndFolders` - файлы и папки |
| **Искать в подпапках** | `bool` | `false` | Рекурсивный поиск во всех вложенных директориях |
| **Таймаут поиска (сек)*** | `int` | `60` | Максимальное время выполнения поиска в секундах |

**Примечание:** Параметры, отмеченные звездочкой (*), являются обязательными для заполнения.

## Выходные параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| **Найденные элементы** | `List<string>` | Список полных путей к найденным файлам и/или папкам |
| **Количество элементов** | `int` | Общее количество найденных элементов |

## Типы фильтрации

### 1. Wildcard (Маски с подстановочными символами)

Используется для простых паттернов поиска.

| Маска | Описание | Примеры совпадений |
|-------|----------|-------------------|
| `*.txt` | Все текстовые файлы | `file.txt`, `document.txt`, `readme.txt` |
| `report_*.xlsx` | Excel файлы с префиксом | `report_2025.xlsx`, `report_final.xlsx` |
| `data_?.csv` | CSV с одним символом | `data_1.csv`, `data_A.csv` |
| `*.log` | Все лог файлы | `app.log`, `error.log`, `debug.log` |
| `test_*_result.*` | Сложные паттерны | `test_123_result.xml`, `test_abc_result.json` |
| `*` | Все элементы | Любые файлы и папки |

**Символы wildcard:**
- `*` - заменяет любое количество любых символов (включая 0)
- `?` - заменяет ровно один любой символ

**Когда использовать:** Для большинства задач поиска. Простой и понятный синтаксис.

### 2. Regex (Регулярные выражения)

Используется для сложной фильтрации с проверкой формата.

| Паттерн | Описание | Примеры совпадений |
|---------|----------|-------------------|
| `^report_\d{8}\.xlsx$` | Excel с 8 цифрами | `report_20250215.xlsx` |
| `^log_\d{4}-\d{2}-\d{2}\.txt$` | Лог с датой | `log_2025-02-15.txt` |
| `^[A-Z]{3}\d{4}\.pdf$` | PDF с кодом | `ABC1234.pdf`, `XYZ5678.pdf` |
| `.*\.(jpg\|png\|gif)$` | Файлы изображений | `photo.jpg`, `image.png`, `icon.gif` |
| `^backup_\d{14}\.zip$` | Архив с timestamp | `backup_20250215143000.zip` |

**Основные символы regex:**
- `^` - начало строки
- `$` - конец строки
- `\d` - любая цифра (0-9)
- `{n}` - ровно n повторений
- `[A-Z]` - любая заглавная буква
- `\.` - точка (экранированная)
- `|` - или
- `.*` - любое количество любых символов

**Когда использовать:** 
- Когда нужна строгая валидация формата имени
- Для сложных паттернов, которые нельзя выразить через wildcard
- При работе с файлами, имеющими структурированные имена

**Важно:** Regex проверяется только на **имени файла/папки**, а не на полном пути.

## Типы поиска

### FilesOnly (Только файлы)

Активность ищет только файлы, игнорируя папки.

**Пример результата:**
```
C:\Documents\report.txt
C:\Documents\data.xlsx
C:\Documents\photo.jpg
```

### FoldersOnly (Только папки)

Активность ищет только папки, игнорируя файлы.

**Пример результата:**
```
C:\Projects\Project1\
C:\Projects\Project2\
C:\Projects\Archive\
```

**Примечание:** Пути к папкам заканчиваются на `\`

### FilesAndFolders (Файлы и папки)

Активность ищет и файлы, и папки одновременно.

**Пример результата:**
```
C:\Data\backup_2025.zip
C:\Data\backup_folder\
C:\Data\backup_old.zip
```

## Алгоритм работы

### Общая схема

```
1. Запуск активности (начало отсчета таймаута)
   ↓
2. Получение и валидация параметров
   ├─ Проверка пути к директории
   ├─ Проверка паттерна поиска
   └─ Проверка существования директории
   ↓
3. Определение опции поиска
   ├─ TopDirectoryOnly (если "Искать в подпапках" = false)
   └─ AllDirectories (если "Искать в подпапках" = true)
   ↓
4. Выполнение поиска в зависимости от типа
   ├─ FilesOnly: поиск файлов
   ├─ FoldersOnly: поиск папок
   └─ FilesAndFolders: поиск файлов + поиск папок
   ↓
5. Применение фильтрации
   ├─ Wildcard: использование встроенного метода GetFiles/GetDirectories
   └─ Regex: получение всех элементов + фильтрация по regex
   ↓
6. Сортировка результатов по имени (алфавитный порядок)
   ↓
7. Установка выходных параметров
   ├─ Найденные элементы (список путей)
   └─ Количество элементов
   ↓
8. Возврат результата
```

### Псевдокод алгоритма

```csharp
function Search(parameters):
    // Определение режима поиска
    searchOption = parameters.SearchInSubfolders 
        ? SearchOption.AllDirectories 
        : SearchOption.TopDirectoryOnly
    
    results = []
    
    // Поиск файлов
    if parameters.SearchType in [FilesOnly, FilesAndFolders]:
        files = SearchFiles(directory, pattern, filterType, searchOption)
        results.AddRange(files)
    
    // Поиск папок
    if parameters.SearchType in [FoldersOnly, FilesAndFolders]:
        folders = SearchFolders(directory, pattern, filterType, searchOption)
        results.AddRange(folders)
    
    // Сортировка и возврат
    return results.OrderBy(name)
```

## Особенности работы

### 🔍 Рекурсивный поиск

Когда включена опция "Искать в подпапках":
- Активность просматривает все вложенные директории
- Глубина вложенности не ограничена
- Может занять длительное время на больших структурах

**Рекомендации:**
- Для больших директорий (>10000 файлов) увеличивайте таймаут
- Используйте более специфичные паттерны для ускорения поиска
- При возможности ограничивайте область поиска конкретными подпапками

### ⚡ Производительность

**Факторы, влияющие на скорость:**
- Количество файлов в директории
- Глубина вложенности (при рекурсивном поиске)
- Тип диска (SSD быстрее HDD)
- Сетевые папки (медленнее локальных)
- Антивирус (может замедлять доступ)

**Приблизительное время:**
```
Локальная папка, 1000 файлов: ~100-300 мс
Локальная папка, 10000 файлов: ~500-1500 мс
Локальная папка, 100000 файлов: ~5-15 секунд
Сетевая папка (добавить × 2-5 раз к времени)
```

### 🎯 Сортировка результатов

Все результаты автоматически сортируются по **полному пути** в алфавитном порядке:
- Папки и файлы сортируются вместе
- Регистр не учитывается
- Порядок: цифры → латиница → кириллица

### ⏱️ Механизм таймаута

Активность использует встроенный механизм `PrimoComponentTO`:

**Как работает:**
1. При запуске активности устанавливается таймер = `(Таймаут поиска + 5 сек) × 1000 мс`
2. Если метод `TimedAction` не завершится за это время
3. Автоматически генерируется исключение `TimeoutException`
4. Процесс прерывается

**Рекомендации по таймауту:**
```
Маленькая директория (<1000 файлов): 10-30 секунд
Средняя директория (1000-10000 файлов): 30-60 секунд
Большая директория (>10000 файлов): 60-180 секунд
Сетевая папка: × 2-3 от обычного времени
```

## Обработка ошибок

### Типичные ошибки и решения

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `Директория не найдена` | Указан несуществующий путь | Проверить правильность пути |
| `Путь к директории не может быть пустым` | Не заполнено обязательное поле | Указать путь к директории |
| `Паттерн поиска не может быть пустым` | Не заполнено обязательное поле | Указать паттерн (или `*` для всех файлов) |
| `Некорректный regex паттерн` | Синтаксическая ошибка в regex | Проверить паттерн на https://regex101.com/ |
| `TimeoutException` | Поиск не завершился за отведенное время | Увеличить таймаут или ограничить область поиска |
| `Отказано в доступе` | Нет прав на чтение директории | Запустить от имени администратора или изменить права |
| `IOException` | Директория заблокирована другим процессом | Закрыть программы, использующие директорию |

### ⚡ Оптимальные настройки

```
Для локальных дисков:
- Таймаут: 30-60 секунд
- Рекурсивный поиск: по необходимости

Для сетевых папок:
- Таймаут: 120-180 секунд
- Рекурсивный поиск: избегать, если возможно

Для очень больших структур:
- Таймаут: 300+ секунд
- Использовать специфичные паттерны
- По возможности искать в конкретных подпапках
```

### 💡 Лучшие практики

1. **Используйте специфичные паттерны**
   - ❌ Плохо: `"*"` (ищет все)
   - ✅ Хорошо: `"report_*.xlsx"` (конкретный тип файлов)

2. **Ограничивайте область поиска**
   - ❌ Плохо: Искать в `C:\` с рекурсией
   - ✅ Хорошо: Искать в `C:\Projects\Current` без рекурсии

3. **Выбирайте правильный тип фильтрации**
   - Wildcard - для простых задач (быстрее)
   - Regex - только когда действительно нужна сложная валидация

4. **Настраивайте таймауты с запасом**
   ```
   Ожидаемое время поиска × 2 = Минимальный таймаут
   ```

5. **Проверяйте результат**
   ```csharp
   if (foundFiles.Count == 0)
   {
       // Обработка случая, когда ничего не найдено
   }
   ```

6. **Используйте правильный тип поиска**
   - `FilesOnly` - если нужны только файлы (быстрее)
   - `FoldersOnly` - если нужны только папки
   - `FilesAndFolders` - только когда действительно нужно и то, и другое

## Диагностика и отладка

### 🔍 Как проверить работу активности?

1. **Проверьте количество найденных элементов**
   ```
   Если ItemsCount = 0:
   - Проверьте правильность паттерна
   - Убедитесь, что файлы существуют
   - Проверьте, включен ли рекурсивный поиск
   ```

2. **Проверьте первые элементы списка**
   ```csharp
   // Вывести первые 5 найденных элементов в лог
   foreach (var item in foundItems.Take(5))
   {
       Log(item);
   }
   ```

3. **Измерьте время выполнения**
   ```
   Используйте выходной параметр "Время выполнения"
   - Если время близко к таймауту → увеличьте таймаут
   - Если время маленькое, но ничего не найдено → проверьте паттерн
   ```

### ⚠️ Частые проблемы

**Проблема 1**: Ничего не найдено, хотя файлы есть
- **Причина**: Паттерн не соответствует именам файлов
- **Решение**: 
  - Проверьте регистр (regex учитывает регистр по умолчанию)
  - Используйте паттерн `*` для проверки
  - Убедитесь в правильности wildcard/regex синтаксиса

**Проблема 2**: Таймаут при поиске
- **Причина**: Слишком большая директория или медленный диск
- **Решение**: 
  - Увеличьте таймаут до 120-180 секунд
  - Используйте более специфичный паттерн
  - Ограничьте область поиска
  - Отключите рекурсивный поиск

**Проблема 3**: Regex паттерн выдает ошибку
- **Причина**: Синтаксическая ошибка в регулярном выражении
- **Решение**: 
  - Проверьте паттерн на https://regex101.com/
  - Экранируйте специальные символы (`\.` для точки)
  - Используйте `^` и `$` для точного совпадения

**Проблема 4**: Найдены не все файлы
- **Причина**: Отключен рекурсивный поиск
- **Решение**: 
  - Включите "Искать в подпапках"
  - Или укажите точный путь к нужной подпапке

**Проблема 5**: Отказано в доступе
- **Причина**: Недостаточно прав для чтения директории
- **Решение**: 
  - Запустите робота от имени администратора
  - Измените права доступа к папке
  - Используйте другую директорию

**Проблема 6**: Находятся папки вместо файлов (или наоборот)
- **Причина**: Неправильно выбран тип поиска
- **Решение**: 
  - Проверьте параметр "Что искать"
  - `FilesOnly` - только файлы
  - `FoldersOnly` - только папки
  - `FilesAndFolders` - оба типа

**Проблема 7**: Результаты в неожиданном порядке
- **Причина**: Результаты сортируются по полному пути
- **Решение**: 
  - Это нормальное поведение (алфавитная сортировка)
  - При необходимости отсортируйте список вручную после получения

## Технические детали

### Зависимости
- .NET Framework 3.5+
- System.IO
- System.Linq
- System.Text.RegularExpressions
- System.Collections.Generic

### Архитектура кода

**Основные компоненты:**
- `SearchParameters` - класс для хранения параметров поиска
- `SearchType` - enum для типа поиска (Files/Folders/Both)
- `SearchFilterType` - enum для типа фильтрации (Wildcard/Regex)

**Ключевые методы:**
- `GetAndValidateParameters()` - получение и валидация параметров
- `SearchItems()` - главный метод поиска
- `SearchFiles()` - поиск файлов с фильтрацией
- `SearchFolders()` - поиск папок с фильтрацией

### Потоки выполнения
- Активность выполняется **синхронно** в основном потоке
- Использует встроенный механизм `PrimoComponentTO` для таймаута
- Не создает дополнительные потоки или задачи
- Таймаут контролируется на уровне SDK

### Производительность

**Оптимизации:**
- Использование встроенных методов `GetFiles`/`GetDirectories` для Wildcard
- Компиляция Regex с флагом `RegexOptions.Compiled`
- LINQ запросы с ленивым выполнением
- Однократная сортировка результатов

**Сложность алгоритмов:**
- Wildcard поиск: O(n) где n - количество элементов в директории
- Regex поиск: O(n × m) где m - сложность regex паттерна
- Сортировка: O(n log n) где n - количество найденных элементов

### Ограничения
- Максимальная длина пути: 260 символов (ограничение Windows)
- Максимальное количество результатов: ограничено только памятью
- Минимальный таймаут: 5 секунд (рекомендуется 10+)
- Regex паттерн применяется только к **имени** файла/папки, не к полному пути

### Особенности реализации

**Отличия Wildcard vs Regex:**
```csharp
// Wildcard - быстро, использует встроенные методы
dirInfo.GetFiles("*.txt", searchOption)

// Regex - медленнее, требует перебора всех файлов
dirInfo.GetFiles("*", searchOption)
    .Where(f => regex.IsMatch(f.Name))
```

**Формат путей к папкам:**
- Папки всегда заканчиваются на `\`
- Пример: `C:\Projects\Folder1\`
- Это позволяет легко отличить папки от файлов в результатах

## Сравнение с другими активностями

### SearchFilesBack vs WaitForFileBack

| Функция | SearchFilesBack | WaitForFileBack |
|---------|-----------------|-----------------|
| **Назначение** | Поиск существующих файлов | Ожидание появления файла |
| **Скорость** | Быстрая (мгновенный результат) | Медленная (ожидание события) |
| **Режим** | Синхронный | Асинхронный с таймаутом |
| **Результат** | Список всех найденных | Один файл |
| **Поиск папок** | ✅ Да | ❌ Нет |
| **Рекурсия** | ✅ Да | ❌ Нет (только одна директория) |

**Когда использовать SearchFilesBack:**
- Нужно найти все файлы по маске
- Файлы уже существуют
- Нужен список для массовой обработки
- Нужно искать папки

**Когда использовать WaitForFileBack:**
- Нужно дождаться появления нового файла
- Файл может появиться в будущем
- Важно отследить момент появления
- Нужна проверка стабильности размера
