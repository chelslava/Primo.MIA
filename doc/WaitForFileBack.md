# Активность "Ожидание файла" (WaitForFileBack)

## Описание

Активность предназначена для ожидания появления файла в указанной директории с гибкими настройками мониторинга и фильтрации. Поддерживает два режима работы: ожидание **нового файла** (которого не было при запуске) или **любого файла** по заданной маске.

## Основные возможности

- ✅ **Два режима работы**: ожидание нового файла или любого существующего файла
- ✅ **Три типа фильтрации**: точное совпадение, wildcard маски (`*.txt`), regex паттерны
- ✅ Ожидание завершения записи файла (стабильность размера)
- ✅ Гибкая настройка таймаутов и интервалов проверки
- ✅ Детальная информация о найденном файле
- ✅ Возможность выброса исключения при таймауте
- ✅ Оптимизированная архитектура с использованием LINQ

## Входные параметры

### Основные параметры

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| **Режим ожидания** | `WaitFileMode` | `WaitForNewFile` | Режим работы активности:<br>• `WaitForNewFile` - ожидать новый файл (которого не было при запуске)<br>• `WaitForAnyFile` - ожидать любой файл по маске |
| **Путь к директории*** | `string` | - | Полный путь к директории для мониторинга<br>Пример: `"C:\Downloads"` |
| **Тип фильтрации** | `FileFilterType` | `Wildcard` | Способ фильтрации файлов:<br>• `Exact` - точное совпадение имени<br>• `Wildcard` - использование `*` и `?`<br>• `Regex` - регулярные выражения |
| **Маска файла*** | `string` | `"*"` | Маска или паттерн для поиска файлов<br>Зависит от выбранного типа фильтрации |

### Настройки таймаутов

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| **Таймаут (сек)*** | `int` | `30` | Максимальное время ожидания файла в секундах |
| **Интервал проверки (мс)*** | `int` | `500` | Интервал между проверками наличия файла |
| **Время стабильности (мс)*** | `int` | `2000` | Время, в течение которого размер файла должен быть стабильным |

| Параметр | Тип | По умолчанию | Описание |

## Режимы работы активности

### Режим 1: WaitForNewFile (Ожидание нового файла)

**Описание:** Активность отслеживает только файлы, которые **появились после** начала её работы.

**Как работает:**
1. При запуске активность запоминает все существующие файлы в директории
2. Периодически проверяет наличие новых файлов, соответствующих маске
3. Возвращает первый найденный файл, которого не было в начальном списке

**Когда использовать:**
- Ожидание загрузки файла из веб-приложения
- Мониторинг появления новых отчетов
- Обработка файлов по мере их создания

### Режим 2: WaitForAnyFile (Ожидание любого файла)

**Описание:** Активность ищет **любой файл**, соответствующий маске, независимо от времени его создания.

**Как работает:**
1. Активность периодически проверяет директорию
2. Ищет файлы, соответствующие маске
3. Возвращает первый найденный файл (самый старый по времени создания)

**Когда использовать:**
- Проверка наличия конфигурационного файла
- Ожидание существующего файла, который мог быть заблокирован
- Повторная обработка файлов

## Типы фильтрации файлов

### 1. Exact (Точное совпадение)

Используется для поиска файла с точным именем.

```
Тип фильтрации: Exact
Маска файла: "report.xlsx"

Найдет только: report.xlsx
Не найдет: report_2025.xlsx, Report.xlsx, report.xls
```

**Когда использовать:** Когда известно точное имя файла.

### 2. Wildcard (Маски с подстановочными символами)

Используется для поиска файлов по шаблону с `*` и `?`.

| Маска | Описание | Примеры совпадений |
|-------|----------|-------------------|
| `*.txt` | Все текстовые файлы | `file.txt`, `document.txt`, `data.txt` |
| `report_*.xlsx` | Excel файлы начинающиеся с "report_" | `report_2025.xlsx`, `report_final.xlsx` |
| `data_?.csv` | CSV файлы с одним символом после "data_" | `data_1.csv`, `data_A.csv` |
| `*.log` | Все лог файлы | `app.log`, `error.log`, `system.log` |
| `test_*_result.xml` | Файлы с шаблоном | `test_123_result.xml`, `test_abc_result.xml` |
| `*` | Все файлы | Любые файлы в директории |

**Символы wildcard:**
- `*` - заменяет любое количество любых символов (включая 0)
- `?` - заменяет ровно один любой символ

**Когда использовать:** Для большинства задач поиска файлов. Это самый универсальный и понятный режим.

### 3. Regex (Регулярные выражения)

Используется для сложной фильтрации с проверкой формата имени файла.

| Паттерн | Описание | Примеры совпадений |
|---------|----------|-------------------|
| `^report_\d{8}\.xlsx$` | Excel с 8 цифрами | `report_20250215.xlsx` |
| `^invoice_[A-Z]{3}\d{4}\.pdf$` | PDF счета с кодом | `invoice_ABC1234.pdf` |
| `^data_\d{4}-\d{2}-\d{2}\.csv$` | CSV с датой | `data_2025-02-15.csv` |
| `^log_\d{14}\.txt$` | Лог с timestamp | `log_20250215143000.txt` |
| `.*\.(jpg\|png\|gif)$` | Файлы изображений | `photo.jpg`, `image.png` |

**Основные символы regex:**
- `^` - начало строки
- `$` - конец строки
- `\d` - любая цифра (0-9)
- `{n}` - ровно n повторений
- `[A-Z]` - любая заглавная буква
- `\.` - точка (экранированная)
- `|` - или

**Когда использовать:** 
- Когда нужна строгая валидация формата имени файла
- Для сложных паттернов, которые нельзя выразить через wildcard
- При работе с файлами, имеющими структурированные имена

**Важно:** Regex проверяется только на **имени файла**, а не на полном пути.

## Алгоритм работы

### Общая схема

```
1. Запуск активности
   ↓
2. Получение и валидация параметров
   ├─ Проверка пути к директории
   ├─ Проверка маски файла
   └─ Проверка числовых параметров
   ↓
3. Выбор режима работы
   ├─ WaitForNewFile: сохранение списка существующих файлов
   └─ WaitForAnyFile: пропуск этого шага
   ↓
4. Цикл проверки (каждые "Интервал проверки" мс):
   ├─ Получение файлов из директории
   ├─ Применение фильтра по типу (Exact/Wildcard/Regex)
   ├─ Применение фильтра по режиму (новый/любой)
   ├─ Сортировка по времени создания
   └─ Выбор первого файла
   ↓
5. Если файл найден:
   ├─ Если "Ожидать завершения записи" = true:
   │  ├─ Мониторинг размера файла
   │  ├─ Ожидание стабильности "Время стабильности" мс
   │  └─ Возврат файла
   └─ Иначе: возврат файла сразу
   ↓
6. Если таймаут истек:
   ├─ Если "Ошибка при таймауте" = true:
   │  └─ Выброс исключения TimeoutException
   └─ Иначе: возврат с флагом "Файл найден" = false
```

### Детальный алгоритм поиска файла

```csharp
// Псевдокод алгоритма
function FindFile(parameters):
    if parameters.Mode == WaitForNewFile:
        existingFiles = GetExistingFiles(directory)
        filter = file => !existingFiles.Contains(file) AND MatchesPattern(file)
    else:
        filter = file => MatchesPattern(file)
    
    startTime = Now()
    
    while (Now() - startTime) < parameters.Timeout:
        files = GetFilesFromDirectory(directory)
        matchedFiles = files.Where(filter).OrderBy(CreationTime)
        
        if matchedFiles.Any():
            foundFile = matchedFiles.First()
            
            if parameters.WaitForStability:
                if WaitForStability(foundFile):
                    return foundFile
                else:
                    return null // Таймаут стабильности
            
            return foundFile
        
        Sleep(parameters.CheckInterval)
    
    return null // Таймаут
```

## Особенности работы

### 🎯 Режимы работы

**WaitForNewFile (Ожидание нового файла):**
- Файл считается новым, если он **отсутствовал** в директории на момент запуска активности
- Подходит для: мониторинга загрузок, обработки поступающих файлов, интеграций

**WaitForAnyFile (Ожидание любого файла):**
- Ищет любой файл, соответствующий маске, независимо от времени создания
- Подходит для: проверки наличия файлов, повторной обработки, ожидания разблокировки

### 🔍 Логика фильтрации

Фильтрация файлов происходит в два этапа:

1. **Фильтр по типу** (Exact/Wildcard/Regex) - применяется к имени файла
2. **Фильтр по режиму** (новый/любой) - проверяет существовал ли файл ранее

Оба фильтра объединяются через логическое **И** (AND).

### ⚙️ Ожидание завершения записи

Когда включена опция "Ожидать завершения записи":
- Активность проверяет размер файла каждые "Интервал проверки" мс
- Если размер изменился, таймер стабильности сбрасывается
- Если размер не меняется в течение "Время стабильности" мс, файл считается записанным
- Полезно при загрузке больших файлов или копировании по сети

**Пример:**
```
Файл появился в 10:00:00
10:00:00 - размер 1000 байт (начало отсчета)
10:00:01 - размер 5000 байт (сброс таймера)
10:00:02 - размер 10000 байт (сброс таймера)
10:00:03 - размер 10000 байт (стабильно)
10:00:05 - размер 10000 байт (стабильно 2 секунды) → файл готов!
```

### 🎯 Возврат первого файла

Если несколько файлов соответствуют условиям поиска:
- Файлы сортируются по времени **создания** (CreationTime)
- Возвращается **самый старый** файл
- Это гарантирует обработку файлов в порядке их появления (FIFO)

### ⏱️ Управление таймаутами

```
Общий таймаут = Таймаут (сек) × 1000 мс

Структура таймаута:
├─ Время на появление файла
└─ Время на стабилизацию размера (если включено)

Рекомендации:
- Для мелких файлов (<1 МБ): Таймаут = 30-60 сек
- Для средних файлов (1-10 МБ): Таймаут = 60-180 сек
- Для больших файлов (>10 МБ): Таймаут = 180-600 сек
- Добавьте запас 50-100% от ожидаемого времени
```

### 🔄 Оптимизация производительности

Активность использует оптимизированную архитектуру:

1. **HashSet для проверки новизны** - O(1) сложность проверки
2. **LINQ для фильтрации** - функциональный подход, читаемый код
3. **Компиляция Regex** - паттерны компилируются один раз
4. **Единый универсальный метод поиска** - отсутствие дублирования кода
5. **Ленивое выполнение LINQ** - обработка только необходимых файлов

## Обработка ошибок

### Типичные ошибки и решения

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `Директория не найдена` | Указан несуществующий путь | Проверить правильность пути к директории |
| `Путь к директории не может быть пустым` | Не заполнено обязательное поле | Указать путь к директории |
| `Маска файла не может быть пустой` | Не заполнено обязательное поле | Указать маску файла |
| `Некорректный regex паттерн` | Синтаксическая ошибка в regex | Проверить корректность regex выражения |
| `Таймаут должен быть больше нуля` | Некорректное значение | Указать положительное значение |
| `Таймаут ожидания нового файла истек` | Файл не появился за отведенное время | Увеличить таймаут или проверить условия |

## Диагностика и отладка

### 🔍 Как проверить работу активности?

1. **Проверьте выходной параметр "Время ожидания"**
   - Если время ≈ таймаут → файл не появился
   - Если время < таймаут → файл был найден

2. **Используйте логирование**
   ```
   Запишите в лог:
   - Файл найден: {fileFound}
   - Путь к файлу: {filePath}
   - Время ожидания: {waitTime} мс
   ```

3. **Тестируйте на заранее подготовленных файлах**
   - Создайте тестовую директорию
   - Скопируйте туда файл во время работы активности
   - Проверьте, что он обнаружен

### ⚠️ Частые проблемы

**Проблема 1**: Активность не находит файл в режиме WaitForNewFile, хотя он есть
- **Причина**: Файл существовал до запуска активности
- **Решение**: 
  - Используйте режим `WaitForAnyFile` если файл может уже существовать
  - Или удалите файл перед запуском активности

**Проблема 2**: Маска не совпадает с именем файла
- **Причина**: Неправильный паттерн для выбранного типа фильтрации
- **Решение**: 
  - Для Wildcard: используйте `*.xlsx` вместо `*.xls`
  - Для Regex: проверьте паттерн на https://regex101.com/
  - Для Exact: убедитесь что имя совпадает точно (включая регистр)

**Проблема 3**: Активность завершается по таймауту слишком рано
- **Причина**: Файл копируется дольше установленного таймаута
- **Решение**: 
  - Увеличьте таймаут (например, с 30 до 120 секунд)
  - Включите "Ожидать завершения записи"
  - Увеличьте время стабильности для больших файлов

**Проблема 4**: Regex паттерн выдает ошибку
- **Причина**: Синтаксическая ошибка в регулярном выражении
- **Решение**: 
  - Используйте инструменты для тестирования regex
  - Проверьте экранирование специальных символов (`\.` для точки)
  - Убедитесь что паттерн применяется к имени файла, а не к пути

**Проблема 5**: Файл найден, но пустой или неполный
- **Причина**: Файл еще записывается на диск
- **Решение**: 
  - Включите "Ожидать завершения записи" = ✓
  - Увеличьте "Время стабильности" (например, до 5000 мс)

**Проблема 6**: Активность находит не тот файл
- **Причина**: В директории несколько файлов соответствуют маске
- **Решение**: 
  - Сделайте маску более специфичной
  - Используйте Regex для точной валидации формата
  - Проверьте что активность возвращает самый старый файл (по CreationTime)

**Проблема 7**: Активность "зависает" на долгое время
- **Причина**: Очень большой таймаут и файл не появляется
- **Решение**: 
  - Уменьшите таймаут до разумных значений (30-120 сек)
  - Используйте "Ошибка при таймауте" для быстрого прерывания
  - Проверьте что путь к директории корректен

## Технические детали

### Зависимости
- .NET Framework 3.5+
- System.IO
- System.Linq
- System.Text.RegularExpressions
- System.Collections.Generic

### Архитектура кода

**Основные компоненты:**
- `SearchParameters` - класс для хранения параметров поиска
- `WaitFileMode` - enum для режима работы (новый/любой файл)
- `FileFilterType` - enum для типа фильтрации (Exact/Wildcard/Regex)

**Ключевые методы:**
- `GetAndValidateParameters()` - получение и валидация всех параметров
- `FindFile()` - главный метод поиска с выбором режима
- `SearchForFile()` - универсальный метод поиска с фильтрацией
- `CreateFileFilter()` - фабрика создания фильтров
- `WaitForFileStability()` - ожидание стабильности размера

### Потоки выполнения
- Активность выполняется **синхронно** в основном потоке
- Использует `Thread.Sleep()` для интервалов проверки
- Не блокирует UI потоки RPA платформы
- Не создает дополнительные потоки или задачи

### Производительность

**Оптимизации:**
- HashSet для O(1) проверки новизны файлов
- Компиляция Regex с флагом `RegexOptions.Compiled`
- LINQ запросы с ленивым выполнением
- Единый универсальный метод поиска (нет дублирования кода)
- Минимальное использование памяти (хранится только список путей)

**Сложность алгоритмов:**
- Проверка новизны файла: O(1) благодаря HashSet
- Фильтрация файлов: O(n) где n - количество файлов в директории
- Сортировка найденных файлов: O(m log m) где m - количество совпадений

### Ограничения
- Максимальное количество файлов в директории: не ограничено (зависит от памяти)
- Размер имени файла: до 260 символов (ограничение Windows)
- Regex паттерн: без ограничений по сложности
- Минимальный интервал проверки: 100 мс (рекомендуется 500+ мс)
