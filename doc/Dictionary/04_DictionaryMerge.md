# Словарь: Объединить

> **Группа:** MIA → Словари  
> **Класс:** `DictionaryMergeBack`  
> **Тип результата:** `Dictionary<string, string>`

## Назначение

Объединяет два `Dictionary<string, string>` в один новый словарь. Оба входных словаря **не изменяются**. Стратегия разрешения конфликтов при совпадении ключей задаётся отдельным параметром.

---

## Параметры

### Входные

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| **Первый словарь** | `Dictionary<string, string>` | Да | Базовый словарь для слияния |
| **Второй словарь** | `Dictionary<string, string>` | Да | Дополнительный словарь для слияния |
| **Стратегия при конфликте** | `DictionaryMergeStrategy` | Да | Поведение при совпадении ключей (по умолч. `KeepSecond`) |

### Выходные

| Параметр | Тип | Описание |
|---|---|---|
| **Результирующий словарь** | `Dictionary<string, string>` | Объединённый словарь |
| **Количество элементов** | `int` | Размер результата |
| **Были конфликты ключей** | `bool` | `true` если обнаружены совпадающие ключи |
| **Конфликтующие ключи** | `List<string>` | Список ключей присутствовавших в обоих словарях (отсортирован) |

---

## Стратегии при конфликте ключей

### `KeepFirst`
При совпадении ключей сохраняется значение из **первого** словаря. Из второго добавляются только те ключи, которых нет в первом.

```
Первый:  { "host": "server1", "port": "5432" }
Второй:  { "host": "server2", "db": "prod" }

Стратегия: KeepFirst
→ Результат: { "host": "server1", "port": "5432", "db": "prod" }
              ↑ значение из первого сохранено
```

### `KeepSecond` *(по умолчанию)*
При совпадении ключей сохраняется значение из **второго** словаря. Второй словарь полностью «перекрывает» первый в случае конфликтов.

```
Первый:  { "host": "server1", "port": "5432" }
Второй:  { "host": "server2", "db": "prod" }

Стратегия: KeepSecond
→ Результат: { "host": "server2", "port": "5432", "db": "prod" }
              ↑ значение из второго победило
```

### `ThrowOnDuplicate`
При обнаружении хотя бы одного совпадающего ключа выбрасывается исключение со списком конфликтующих ключей.

```
Первый:  { "host": "server1", "port": "5432" }
Второй:  { "host": "server2", "db": "prod" }

Стратегия: ThrowOnDuplicate
→ Ошибка: "Конфликт при слиянии — дублирующиеся ключи: host. Смените стратегию..."
```

---

## Таблица стратегий

| Стратегия | Конфликтующий ключ | Уникальные из первого | Уникальные из второго |
|---|---|---|---|
| `KeepFirst` | Значение из 1-го | ✅ | ✅ |
| `KeepSecond` | Значение из 2-го | ✅ | ✅ |
| `ThrowOnDuplicate` | ❌ Исключение | — | — |

## Примеры использования

**Объединить конфигурацию по умолчанию с пользовательской (пользователь имеет приоритет):**
```
Первый словарь:       defaultConfig   ← { "timeout": "30", "retries": "3", "host": "localhost" }
Второй словарь:       userConfig      ← { "host": "prod-server", "port": "8080" }
Стратегия:            KeepSecond
→ Результат: { "timeout": "30", "retries": "3", "host": "prod-server", "port": "8080" }
→ Были конфликты: true
→ Конфликтующие ключи: ["host"]
```

**Добавить новые ключи без перезаписи существующих:**
```
Первый словарь:   mainDict
Второй словарь:   extensionsDict
Стратегия:        KeepFirst
→ Из второго добавятся только новые ключи, существующие не изменятся
```

**Убедиться что словари не пересекаются:**
```
Стратегия:   ThrowOnDuplicate
→ При любом совпадении ключей — исключение с перечислением конфликтов
```

**Проверить конфликты без прерывания процесса:**
```
Стратегия:              KeepSecond
Были конфликты ключей:  hadConflicts    ← bool
Конфликтующие ключи:    conflictList    ← List<string>

→ Затем проверить: если hadConflicts = true — залогировать conflictList
```

---

## Возможные ошибки

| Ошибка | Причина |
|---|---|
| `ArgumentNullException` | Первый или второй словарь = null |
| `InvalidOperationException` | Обнаружены конфликтующие ключи при стратегии `ThrowOnDuplicate` |

---

## Заметки

- `Конфликтующие ключи` заполняется **всегда** независимо от стратегии — удобно для последующего логирования или анализа
- Конфликтующие ключи возвращаются в **алфавитном** порядке
- При пустом словаре (0 элементов) операция выполняется успешно — возвращается копия непустого
- Порядок элементов в результирующем словаре не гарантирован
