# Словарь: Фильтровать

> **Группа:** MIA → Словари  
> **Класс:** `DictionaryFilterBack`  
> **Тип результата:** `Dictionary<string, string>`

## Назначение

Фильтрует `Dictionary<string, string>` и возвращает новый словарь, содержащий только пары, прошедшие условие. Оригинальный словарь **не изменяется**.

Логика фильтрации разделена на два независимых параметра:
- **Где искать** (`Target`) — к какому полю пары применять условие
- **Метод поиска** (`Method`) — как именно сравнивать строки

Любая комбинация Target + Method допустима — итого 12 вариантов.

---

## Параметры

### Входные

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| **Словарь** | `Dictionary<string, string>` | Да | Входной словарь для фильтрации |
| **Строка поиска / паттерн** | `string` | Да | Подстрока, точная строка, regex или wildcard (зависит от Метода) |
| **Где искать** | `DictionaryFilterTarget` | Да | `Keys` / `Values` / `KeysAndValues` |
| **Метод поиска** | `DictionaryFilterMethod` | Да | `Contains` / `Exact` / `Regex` / `Wildcard` |
| **Учитывать регистр** | `bool` | Нет | `false` по умолчанию — поиск без учёта регистра |

### Выходные

| Параметр | Тип | Описание |
|---|---|---|
| **Результирующий словарь** | `Dictionary<string, string>` | Пары прошедшие фильтр |
| **Прошло фильтр** | `int` | Количество прошедших пар |
| **Отсеяно фильтром** | `int` | Количество отсеянных пар |

---

## Параметр «Где искать» (`Target`)

| Значение | Описание |
|---|---|
| `Keys` | Условие применяется к **ключу** пары |
| `Values` | Условие применяется к **значению** пары |
| `KeysAndValues` | Пара проходит если условие выполнено для ключа **ИЛИ** для значения |

---

## Параметр «Метод поиска» (`Method`)

### `Contains` — содержит подстроку
Пара проходит если поле содержит строку поиска как подстроку.

```
Строка поиска: "error"
Значения:      "critical error occurred", "warning", "error_code_42"
→ Проходят:    "critical error occurred", "error_code_42"
```

### `Exact` — точное совпадение
Пара проходит только при полном совпадении поля со строкой поиска.

```
Строка поиска: "active"
Значения:      "active", "inactive", "Active"
Учитывать регистр: false
→ Проходят:    "active", "Active"
```

### `Regex` — регулярное выражение
Строка поиска интерпретируется как регулярное выражение. Используется `Regex.IsMatch` — совпадение может быть частичным (если якоря `^` и `$` не указаны явно).

```
Строка поиска: "^\d{4}-\d{2}-\d{2}$"
Значения:      "2024-01-15", "15.01.2024", "2024-13-01"
→ Проходят:    "2024-01-15"
```

```
Строка поиска: "\d+"     ← частичное совпадение (без якорей)
Значения:      "abc123", "nodigits", "42"
→ Проходят:    "abc123", "42"
```

> ⚠️ Синтаксис регулярного выражения проверяется на этапе валидации формы. Некорректный паттерн не позволит сохранить активность.

### `Wildcard` — wildcard-паттерн
Поддерживаемые символы:
- `*` — любое количество любых символов (в т.ч. пустая строка)
- `?` — ровно один любой символ
- Все остальные символы — литеральные (включая `.`, `(`, `[` и т.д.)

Сопоставление всегда **полное** — паттерн проверяет всю строку целиком.

```
Паттерн: "order_*_2024"
Значения: "order_123_2024", "order_abc_2024", "order_2023"
→ Проходят: "order_123_2024", "order_abc_2024"

Паттерн: "user_?@domain.com"
Значения: "user_a@domain.com", "user_ab@domain.com", "admin@domain.com"
→ Проходят: "user_a@domain.com"
```

---

## Флаг «Учитывать регистр»

Работает для **всех** методов поиска и для **обоих** полей (ключ и значение):

| Значение | Поведение |
|---|---|
| `false` (по умолч.) | `"Hello"` == `"hello"` == `"HELLO"` |
| `true` | `"Hello"` ≠ `"hello"` |

---

## Таблица комбинаций Target + Method

| Target \ Method | Contains | Exact | Regex | Wildcard |
|---|---|---|---|---|
| **Keys** | Ключ содержит подстроку | Ключ равен строке | Ключ совпадает с regex | Ключ совпадает с паттерном |
| **Values** | Значение содержит подстроку | Значение равно строке | Значение совпадает с regex | Значение совпадает с паттерном |
| **KeysAndValues** | Ключ ИЛИ значение содержат подстроку | Ключ ИЛИ значение равно строке | Ключ ИЛИ значение совпадают с regex | Ключ ИЛИ значение совпадают с паттерном |

## Примеры использования

**Найти все записи об ошибках:**
```
Словарь:         logDict        ← { "event_1": "info: start", "event_2": "error: failed", ... }
Строка поиска:   "error"
Где искать:      Values
Метод поиска:    Contains
Учитывать регистр: false
→ Результат:     { "event_2": "error: failed", ... }
```

**Оставить только ключи начинающиеся с "db_":**
```
Словарь:         configDict
Строка поиска:   "db_*"
Где искать:      Keys
Метод поиска:    Wildcard
→ Результат:     только записи с ключами типа "db_host", "db_port", "db_name"
```

**Найти записи с датами в значениях:**
```
Строка поиска:   "\d{4}-\d{2}-\d{2}"
Где искать:      Values
Метод поиска:    Regex
→ Результат:     пары где значение содержит дату формата ГГГГ-ММ-ДД
```

**Найти конкретный статус:**
```
Строка поиска:   "ACTIVE"
Где искать:      Values
Метод поиска:    Exact
Учитывать регистр: false
→ Результат:     пары со значением "active", "Active", "ACTIVE" и т.д.
```

## Возможные ошибки

| Ошибка | Причина |
|---|---|
| `ArgumentNullException` | Словарь = null |
| `ArgumentNullException` | Строка поиска = null |
| `ArgumentException` | Пустой Regex или Wildcard паттерн |
| `ArgumentException` | Некорректный синтаксис regex-паттерна |
