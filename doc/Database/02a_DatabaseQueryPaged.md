# БД: Постраничный запрос

> **Группа:** MIA → База данных
> **Класс:** `DatabaseQueryPagedBack`

## Назначение

Выполняет SQL-запрос постранично.

Активность:
- считает общее количество строк через `COUNT(*)`
- возвращает только одну страницу результата
- сообщает metadata по пагинации: `TotalRows`, `TotalPages`, `HasNextPage`, `HasPreviousPage`

## Входные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Provider invariant name` | `string` | Идентификатор ADO.NET-провайдера. От этого значения зависит, какой синтаксис пагинации будет использован: `OFFSET/FETCH`, `LIMIT/OFFSET` или oracle-compatible вариант. |
| `Строка подключения` | `string` | Connection string выбранной БД. Лучше передавать ту же строку подключения, что и в обычных `Query`-активностях, чтобы параметры подключения и права совпадали с остальными шагами процесса. См. примеры для провайдеров в [00_INDEX.md](00_INDEX.md). |
| `ID транзакции` | `string` | Необязательный `transactionId`, если страницу нужно читать в рамках уже открытой DB-транзакции. Это полезно, когда важно зафиксировать единое состояние данных между несколькими SQL-шагами. |
| `SQL / имя процедуры` | `string` | Исходный SQL-запрос без пагинации. Активность сама оборачивает его в подзапрос, строит `COUNT(*)` для общего числа строк и добавляет нужную конструкцию page slicing для текущего провайдера. |
| `Order by` | `string` | Обязательное выражение `ORDER BY`, которое задаёт стабильный и предсказуемый порядок строк между страницами. Без него одна и та же запись может "прыгать" между страницами при повторных запросах. |
| `Номер страницы` | `int` | Номер страницы, начиная с `1`. Если значение меньше `1`, активность использует безопасное значение по умолчанию, чтобы избежать некорректной генерации SQL. |
| `Размер страницы` | `int` | Сколько строк нужно вернуть за один вызов. Обычно это значение подбирают как компромисс между скоростью загрузки, объёмом памяти и удобством дальнейшей обработки. |
| `Параметры` | `Dictionary<string,string>` | Параметры исходного запроса. Они используются и в `COUNT(*)`, и в запросе конкретной страницы, поэтому фильтрация и итоговое количество строк остаются согласованными. |
| `Таймаут команды (сек)` | `int` | Таймаут выполнения для count-запроса и самой выборки страницы. Имеет смысл увеличивать его для тяжёлых отчётных запросов и больших таблиц. |

## Выходные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Таблица-результат` | `DataTable` | Набор строк только для текущей страницы. Его можно сразу передавать дальше по процессу, не загружая весь результат целиком в память. |
| `Количество строк` | `int` | Сколько строк реально попало в текущую страницу. На последней странице это значение часто меньше `Размер страницы`, и это нормальное поведение. |
| `Всего строк` | `int` | Полное количество строк, которое вернул бы исходный запрос без пагинации. Это значение удобно для расчёта прогресса и отображения общей статистики в логах или UI. |
| `Всего страниц` | `int` | Сколько страниц получится при выбранном `Размер страницы`. Значение уже учитывает неполную последнюю страницу. |
| `Есть следующая страница` | `bool` | `true`, если после текущей страницы есть ещё данные и можно безопасно переходить к следующему номеру страницы. |
| `Есть предыдущая страница` | `bool` | `true`, если текущая страница не первая и можно вернуться назад без дополнительной логики проверки. |

## Замечания

- Для SQL Server используется `OFFSET ... FETCH`
- Для PostgreSQL / MySQL / SQLite используется `LIMIT ... OFFSET`
- Для Oracle используется `OFFSET ... FETCH` с oracle-compatible alias
