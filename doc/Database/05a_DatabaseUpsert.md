# БД: Upsert из DataTable

> **Группа:** MIA → База данных
> **Класс:** `DatabaseUpsertBack`

## Назначение

Выполняет key-based upsert из `DataTable`.

Логика:
- по `KeyColumns` выполняется `UPDATE`
- если строка не найдена, выполняется `INSERT`

## Входные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Таблица данных` | `DataTable` | Исходный набор строк, который нужно синхронизировать с целевой таблицей БД. |
| `Provider invariant name` | `string` | Идентификатор ADO.NET-провайдера, определяющий синтаксис параметров и SQL-генерацию. |
| `Строка подключения` | `string` | Connection string выбранной БД. Если upsert запускается внутри DB-транзакции, активность может использовать уже открытое соединение. |
| `ID транзакции` | `string` | Необязательный `transactionId` существующей DB-транзакции. |
| `Таблица-приёмник` | `string` | Таблица, в которую нужно вносить изменения. Поддерживаются fully-qualified имена. |
| `Ключевые колонки` | `List<string>` | Набор колонок, по которым определяется существование строки. Если совпадение найдено — выполняется `UPDATE`, иначе — `INSERT`. |
| `Колонки обновления` | `List<string>` | Какие именно поля обновлять при совпадении по ключу. Если список пуст, активность обновляет все неключевые колонки. |
| `Маппинг колонок` | `Dictionary<string,string>` | Необязательный словарь `SourceColumn -> DestinationColumn`, если имена колонок в `DataTable` и в БД отличаются. |
| `Таймаут команды (сек)` | `int` | Таймаут для `UPDATE`/`INSERT` команд внутри upsert-процесса. |

## Выходные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Вставлено строк` | `int` | Сколько строк не нашлось по ключу и было вставлено как новые записи. |
| `Обновлено строк` | `int` | Сколько строк было найдено по ключу и обновлено на основе входных данных. |

## Замечания

- `KeyColumns` можно задавать как по имени колонки в `DataTable`, так и по имени destination-колонки из маппинга
- `Upsert` выполняется в одной транзакции
- Для `Odbc` и `OleDb` используются позиционные параметры `?`
- Это универсальный row-by-row upsert, ориентированный на совместимость, а не на vendor-specific bulk merge
