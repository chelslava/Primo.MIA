# Документация: Redis активности

> **Группа в студии:** MIA → Redis
> **Драйвер:** StackExchange.Redis
> **Версия:** из NuGet зависимостей проекта

Все активности работают с Redis через пул соединений (`:ConnectionMultiplexer`). Соединения переиспользуются автоматически через кеш по connection string.

## Строки (String)

Самый базовый тип Redis. Используется для кэширования простых значений.

```
Ключ: "user:42:name"
Значение: "Иван"
```

### Пример: кэширование API-ответа

```
1. Redis: Установить
   - Ключ: "api:users:42"
   - Значение: "{...JSON...}"
   - Результат: записано

2. [Другие активности]

3. Redis: Получить
   - Ключ: "api:users:42"
   → Значение: "{...JSON...}"
   → Ключ существует: true
```

---

## Счётчики (INCR)

Атомарное увеличение числового значения. Идеально для генерации ID, rate limiting.

```
Начальное значение: (отсутствует)
After INCR: "1"
After INCR: "2"
After INCR: "3"
```

### Пример: генерация порядкового номера

```
1. Redis: Увеличить счётчик
   - Ключ: "order:counter"
   - Шаг: 1
   → Значение: 1001  (первый вызов)
   → Значение: 1002  (второй вызов)
```

## Хэши (Hash)

Хэш-таблица внутри одного ключа. Удобно для хранения объектов.

```
Ключ: "user:42"
Поля:
  name: "Иван"
  email: "ivan@example.com"
  age: "30"
```

### Операции с хэшем

| Операция | Описание |
|----------|----------|
| HSET | Установить поле |
| HGET | Получить поле |
| HGETALL | Получить все поля |

### Пример: хранение профиля пользователя

```
1. Redis: Хэш: Установить поле
   - Ключ: "user:42"
   - Поле: "name"
   - Значение: "Иван"

2. Redis: Хэш: Установить поле
   - Ключ: "user:42"
   - Поле: "email"
   - Значение: "ivan@example.com"

3. Redis: Хэш: Получить поле
   - Ключ: "user:42"
   - Поле: "name"
   → Значение: "Иван"
```

## Списки (List)

Упорядоченная коллекция строк. FIFO очередь.

```
Ключ: "queue:tasks"
Элементы: [task1, task2, task3]
```

### Операции со списком

| Операция | Описание |
|----------|----------|
| LPUSH | Добавить в начало |
| RPUSH | Добавить в конец |
| LRANGE | Получить диапазон |

### Пример: обработка задач из очереди

```
1. Redis: Список: Добавить
   - Ключ: "queue:tasks"
   - Значение: "task:001"
   - Направление: В конец (RPUSH)

2. Redis: Список: Диапазон
   - Ключ: "queue:tasks"
   - Старт: 0
   - Конец: -1 (все элементы)
   → Элементы: ["task:001"]

3. Redis: Удалить
   - Ключ: "queue:tasks"
```

## Обработка ошибок

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `Строка подключения обязательна` | Пустое поле | Укажите валидный Redis connection string |
| `Ключ обязателен` | Пустое поле | Укажите имя ключа |
| `Ошибка Redis GET: ...` | Ошибка драйвера | Проверьте доступность Redis |

## Подключение к Redis

### Локальный Redis

```
localhost:6379
```

### С авторизацией

```
password:secret@localhost:6379
```

### Кластер Redis

```
redis://password@host1:6379,host2:6379,host3:6379
```

### Sentinel

```
myservice,serviceDiscoveryTimeout=5000,abortConnect=false
```

| Redis | Описание | Пример использования |
|-------|----------|----------------------|
| String | Простая строка | Кэш, сессии |
| Hash | Хэш-таблица | Объекты, профили |

## Производительность

- **StackExchange.Redis** использует мультиплексинг — одно соединение для множества операций
- Пул соединений кешируется по connection string
- INCR — атомарная операция, безопасна для конкурентного доступа
- Все операции синхронные ( blocking )
