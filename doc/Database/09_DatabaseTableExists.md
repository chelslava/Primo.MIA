# БД: Проверить таблицу

> **Группа:** MIA → База данных
> **Класс:** `DatabaseTableExistsBack`

## Назначение

Проверяет, существует ли таблица или view в БД через `GetSchema("Tables")`.

## Входные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Provider invariant name` | `string` | Идентификатор ADO.NET-провайдера, через который будет выполнено чтение schema metadata. От него зависит, какие столбцы и значения вернёт `GetSchema("Tables")`. |
| `Строка подключения` | `string` | Connection string выбранной БД. Рекомендуется использовать ту же строку подключения, с которой позже будут выполняться реальные SQL-операции, чтобы проверка существования отражала тот же каталог, схему и набор прав. См. типовые примеры в [00_INDEX.md](00_INDEX.md). |
| `Имя таблицы` | `string` | Имя таблицы или представления, которое нужно проверить. Обычно сюда передают короткое имя объекта без схемы, а схему указывают отдельным параметром. |
| `Имя схемы` | `string` | Необязательное имя схемы для уточнения поиска, например `dbo`, `public` или имя бизнес-схемы. Особенно полезно, если в БД могут существовать одноимённые таблицы в разных схемах. |
| `Учитывать представления` | `bool` | Если `true`, активность считает `view` допустимым совпадением наряду с обычной таблицей. Это удобно для сценариев, где источник данных может быть реализован как таблица или как представление без изменения процесса. |

## Выходные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Существует` | `bool` | `true`, если таблица или view с указанным именем найдены в metadata выбранного провайдера. `false` означает, что объект не найден либо недоступен текущему пользователю по правам. |

## Замечания

- Проверка выполняется через schema metadata, а не через `SELECT 1 FROM ...`, поэтому она не меняет данные и не требует составления SQL вручную.
- В разных провайдерах чувствительность к регистру, правила схем и наборы `TABLE_TYPE` могут немного отличаться, поэтому для нестандартных БД лучше проверять результат на целевом окружении.
