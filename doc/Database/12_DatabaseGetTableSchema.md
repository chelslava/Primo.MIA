# БД: Схема таблицы

> **Группа:** MIA → База данных
> **Класс:** `DatabaseGetTableSchemaBack`

## Назначение

Возвращает `DataTable` со schema metadata выбранной таблицы.

Подходит для анализа:
- типов колонок
- `nullable`
- порядка колонок
- provider-specific атрибутов, которые возвращает конкретный ADO.NET-провайдер

## Входные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Provider invariant name` | `string` | Идентификатор ADO.NET-провайдера, через который будет вызван `GetSchema("Columns")` или эквивалентное чтение metadata. От него зависит состав возвращаемых полей и их формат. |
| `Строка подключения` | `string` | Connection string выбранной БД. Стоит использовать ту же строку подключения, что и для реальных DB-операций, чтобы schema metadata отражала нужный сервер, каталог и права текущего пользователя. См. примеры в [00_INDEX.md](00_INDEX.md). |
| `Имя таблицы` | `string` | Имя таблицы, metadata которой нужно получить. Обычно это короткое имя объекта без схемы. |
| `Имя схемы` | `string` | Необязательная схема, например `dbo`, `public` или другая доменная схема. Позволяет точнее выбрать объект при наличии одноимённых таблиц. |

## Выходные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Схема таблицы` | `DataTable` | Полная таблица schema metadata по колонкам выбранного объекта. Обычно она содержит имя колонки, тип, длину, nullable, ordinal и другие provider-specific поля. |
| `Количество строк` | `int` | Сколько строк metadata вернул провайдер. На практике это обычно соответствует числу колонок таблицы. |

## Замечания

- Состав столбцов в возвращаемом `DataTable` зависит от провайдера: у SQL Server, PostgreSQL, Oracle и ODBC он может заметно отличаться.
- Активность удобна как диагностический и подготовительный инструмент перед `BulkInsert`, `Upsert`, динамической генерацией SQL и валидацией входных данных.
