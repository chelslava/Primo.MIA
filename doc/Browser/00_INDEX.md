# Документация: Библиотека активностей «Браузер» (MIA)

> **Группа в студии:** MIA → Браузер  
> **Технология:** Selenium WebDriver  
> **Поддерживаемые браузеры:** Chrome, Firefox, Edge

Все активности работают с браузером через Selenium WebDriver и поддерживают управление множественными сессиями через `sessionId`.

## Общие принципы библиотеки

### 1. Управление сессиями
Все активности работают с `sessionId` - уникальным идентификатором экземпляра браузера. Это позволяет:
- Работать с несколькими браузерами одновременно
- Изолировать операции между разными процессами
- Переиспользовать открытые браузеры

### 2. Локаторы элементов
Поддерживаются следующие типы локаторов:
- **Id** - поиск по атрибуту id
- **Name** - поиск по атрибуту name
- **ClassName** - поиск по CSS классу
- **TagName** - поиск по тегу
- **LinkText** - поиск ссылки по точному тексту
- **PartialLinkText** - поиск ссылки по частичному тексту
- **CssSelector** - поиск по CSS селектору
- **XPath** - поиск по XPath выражению

### 3. Таймауты
Все операции поиска элементов поддерживают таймауты:
- По умолчанию: 10 секунд
- Настраиваемый для каждой операции
- Автоматические повторные попытки при временных ошибках

### 4. Обработка ошибок
- Понятные сообщения об ошибках
- Автоматические скриншоты при ошибках (опционально)
- Логирование всех операций
- Retry механизм для нестабильных элементов

### 5. Расширенные возможности
- **Shadow DOM** - работа с веб-компонентами
- **iframe** - автоматическое обнаружение элементов в iframe
- **Множественные окна** - управление вкладками и окнами
- **JavaScript** - выполнение произвольного JS кода

## Архитектура

Все активности наследуют базовый класс `BrowserActivityBase`, который предоставляет:
- Управление WebDriver сессиями
- Поиск элементов с ожиданием
- Retry механизм
- Логирование
- Создание скриншотов
- Работу с Shadow DOM и iframe

```
BrowserActivityBase
├── Driver Management
├── Element Location
├── Retry Mechanism
├── Shadow DOM Support
├── iframe Auto-handling
├── Screenshot on Error
└── Extended Selectors
```

## Требования

### Системные требования
- Windows 10/11 или Windows Server 2016+
- .NET Framework 4.6.1+
- Primo Platform

### Браузеры
- **Chrome** - требуется ChromeDriver
- **Firefox** - требуется GeckoDriver
- **Edge** - требуется EdgeDriver

### Драйверы
Драйверы должны быть установлены и доступны в PATH или указаны явно при открытии браузера.

## Примеры типовых сценариев

### Сценарий 1: Авторизация на сайте
```
1. Браузер: Открыть (Chrome)
2. Браузер: Навигация (https://example.com/login)
3. Элемент: Ввод текста (#username, "user@example.com")
4. Элемент: Ввод текста (#password, "password123")
5. Элемент: Клик (#login-button)
6. Браузер: Ожидание (URL содержит "/dashboard")
```

### Сценарий 2: Извлечение данных из таблицы
```
1. Браузер: Открыть
2. Браузер: Навигация (URL таблицы)
3. Элемент: Информация (table tbody tr) → получить все строки
4. Для каждой строки:
   - Элемент: Информация (td) → получить ячейки
5. Браузер: Закрыть
```

### Сценарий 3: Заполнение формы с файлом
```
1. Браузер: Открыть
2. Браузер: Навигация (URL формы)
3. Элемент: Ввод текста (#name, "Иван Иванов")
4. Элемент: Загрузить файл (#file-input, "C:\document.pdf")
5. Элемент: Выбор из списка (#country, "Россия")
6. Элемент: Клик (#submit)
7. Браузер: Ожидание (элемент .success-message)
```

## Troubleshooting

### Браузер не открывается
- Проверьте наличие драйвера в PATH
- Убедитесь что версия драйвера совпадает с версией браузера
- Проверьте права доступа к файлу драйвера

### Элемент не найден
- Увеличьте таймаут ожидания
- Проверьте правильность локатора
- Используйте [Браузер: Ожидание](23_BrowserWaitFor.md) перед поиском
- Проверьте не находится ли элемент в iframe

### Элемент не кликабелен
- Используйте [Элемент: Прокрутка](11_ElementScrollTo.md) перед кликом
- Дождитесь видимости элемента
- Проверьте не перекрыт ли элемент другими элементами

### Медленная работа
- Используйте CSS селекторы вместо XPath где возможно
- Уменьшите таймауты для быстрых операций
- Используйте headless режим для фоновой работы
