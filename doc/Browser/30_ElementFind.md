# Элемент: Найти

> **Группа:** MIA → Браузер  
> **Класс:** `ElementFindBack`

## Назначение

Ищет один или несколько элементов по локатору в указанной браузерной сессии. В режиме `FindOne` возвращает ID первого найденного элемента, в режиме `FindAll` — список ID и количество совпадений.

## Входные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `Режим поиска` | `FindMode` | `FindOne` — вернуть первый элемент, `FindAll` — вернуть все найденные элементы. |
| `ID сессии браузера` | `string` | Идентификатор открытого браузера, полученный из активности открытия. |
| `Тип локатора` | `ElementLocatorType` | Способ поиска: `Id`, `Name`, `CssSelector`, `XPath` и др. |
| `Значение локатора` | `string` | Сам локатор: селектор, XPath, id и т.д. |
| `Таймаут ожидания (сек)` | `int` | Сколько ждать появления элемента(ов) перед ошибкой. |

## Выходные параметры

| Параметр | Тип | Описание |
|---|---|---|
| `ID элемента` | `string` | Заполняется в режиме `FindOne`. |
| `Список ID элементов` | `List<string>` | Заполняется в режиме `FindAll`. |
| `Количество элементов` | `int` | Число найденных элементов в режиме `FindAll`. |

## Режимы

| Режим | Поведение |
|---|---|
| `FindOne` | Находит первое совпадение и сохраняет его в RepoDict как один элемент. |
| `FindAll` | Находит все совпадения, сохраняет каждый элемент в RepoDict и возвращает список их ID. |

## Пример

```text
Режим поиска: FindAll
ID сессии браузера: "browser-1"
Тип локатора: CssSelector
Значение локатора: ".orders-table tbody tr"
Таймаут ожидания (сек): 10
```

## Примечания

- Активность всегда работает через `sessionId`; без открытой сессии поиск невозможен.
- Для дальнейших действий с найденным элементом удобно передавать `ID элемента` в другие browser-активности.
- Если нужен не только поиск, но и проверка видимости, кликабельности или количества, используйте [31_ElementSearch.md](31_ElementSearch.md).
