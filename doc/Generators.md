# Активность «Генераторы»

**Класс:** `GeneratorsBack`

## 1. GUID

Генерирует глобально уникальный идентификатор (UUID v4).

### Параметры

| Свойство | Тип | Описание |
|---|---|---|
| **Формат GUID** | `GuidFormat` | Формат строкового представления |

### Форматы

| Значение | Пример | Применение |
|---|---|---|
| `N` | `00000000000000000000000000000000` | URL, компактное хранение |
| `D` | `00000000-0000-0000-0000-000000000000` | Стандарт (по умолчанию) |
| `B` | `{00000000-0000-0000-0000-000000000000}` | Конфигурационные файлы |
| `P` | `(00000000-0000-0000-0000-000000000000)` | Альтернативный стиль |
| `X` | `{0x00000000,0x0000,0x0000,{0x00,...}}` | C/C++ код |

### Пример результата

```
D → 3f2504e0-4f89-11d3-9a0c-0305e82c3301
N → 3f2504e04f8911d39a0c0305e82c3301
```

## 2. Имя файла

Генерирует уникальное полное имя файла. Если файл с базовым именем уже существует в директории — автоматически добавляет числовой суффикс.

### Параметры

| Свойство | Тип | Обязательно | Описание |
|---|---|---|---|
| **Директория** | `string` | Нет | Путь к папке. Если пусто — возвращается только имя файла |
| **Базовое имя** | `string` | **Да** | Имя файла без расширения |
| **Расширение** | `string` | Нет | Расширение файла. Точка добавляется автоматически. По умолчанию `.txt` |

### Логика уникальности

```
report.xlsx      → уже существует
report(1).xlsx   → уже существует
report(2).xlsx   → свободно ✓ — вернёт этот путь
```

> Файл **не создаётся** — активность только генерирует имя.

### Пример результата

```
C:\Reports\invoice(3).xlsx
```

## 3. Случайное число

Генерирует случайное целое число в диапазоне **\[Мин, Макс\]** включительно.

### Параметры

| Свойство | Тип | По умолчанию | Описание |
|---|---|---|---|
| **Минимальное значение** | `int` | `0` | Нижняя граница диапазона (включительно) |
| **Максимальное значение** | `int` | `100` | Верхняя граница диапазона (включительно) |

### Пример результата

```
Мин=1, Макс=6 → "4"   (бросок кубика)
Мин=0, Макс=1 → "0"   (монета)
```

> При нечисловых значениях в полях используются значения по умолчанию (0 и 100).  
> Если Мин > Макс — активность завершится с ошибкой.

## 4. Временная метка

Форматирует текущую дату/время (`DateTime.Now`) в строку по выбранному формату.

### Параметры

| Свойство | Тип | Описание |
|---|---|---|
| **Формат даты** | `TimestampFormat` | Предустановленный формат |
| **Кастомный формат** | `string` | Используется только при выборе `Custom` |

### Форматы

#### Компактные — для имён файлов и ID

| Значение | Пример результата | Применение |
|---|---|---|
| `yyyyMMdd_HHmmss` | `20250215_143045` | Стандартные временны́е метки |
| `yyyyMMdd_HHmm` | `20250215_1430` | Ежеминутные файлы |
| `yyyyMMdd` | `20250215` | Ежедневные файлы |
| `yyyyMM` | `202502` | Ежемесячные файлы |
| `yyyyMMddHHmmssfff` | `20250215143045123` | Максимальная уникальность |

#### ISO 8601 — для баз данных и API

| Значение | Пример результата |
|---|---|
| `yyyy_MM_dd` | `2025-02-15` |
| `yyyy_MM_dd_HH_mm_ss` | `2025-02-15 14:30:45` |
| `ISO8601` | `2025-02-15T14:30:45` |
| `ISO8601_ms` | `2025-02-15T14:30:45.123` |

#### Российские — для отчётов и документов

| Значение | Пример результата |
|---|---|
| `dd_MM_yyyy` | `15.02.2025` |
| `dd_MM_yyyy_HH_mm_ss` | `15.02.2025 14:30:45` |
| `dd_MM_yyyy_HH_mm` | `15.02.2025 14:30` |
| `dd_MM_yyyy_slash` | `15/02/2025` |

#### Американские

| Значение | Пример результата |
|---|---|
| `MM_dd_yyyy` | `02/15/2025` |
| `MM_dd_yyyy_HH_mm_ss` | `02/15/2025 14:30:45` |

#### Только время

| Значение | Пример результата |
|---|---|
| `HHmmss` | `14:30:45` |
| `HHmm` | `14:30` |
| `HHmmss_fff` | `14:30:45.123` |

#### Специальные

| Значение | Пример результата | Описание |
|---|---|---|
| `FullDate` | `Суббота, 15 февраля 2025 г.` | Полная дата, зависит от локали системы |
| `Quarter` | `Q1-2025` | Квартал и год |
| `WeekNumber` | `W07-2025` | Номер недели ISO 8601 |
| `UnixTimestamp` | `1739624400` | Секунды с 01.01.1970 00:00:00 UTC |
| `Custom` | *(задаётся вручную)* | Использует поле **Кастомный формат** |

### Кастомный формат

При выборе `Custom` используются стандартные спецификаторы C# `DateTime.ToString()`:

| Спецификатор | Значение | Пример |
|---|---|---|
| `yyyy` / `yy` | Год 4/2 цифры | `2025` / `25` |
| `MM` / `MMM` / `MMMM` | Месяц число/сокр./полный | `02` / `фев` / `февраль` |
| `dd` / `ddd` / `dddd` | День число/сокр./полный | `15` / `Сб` / `Суббота` |
| `HH` / `hh` | Часы 24ч / 12ч | `14` / `02` |
| `mm` | Минуты | `30` |
| `ss` | Секунды | `45` |
| `fff` | Миллисекунды | `123` |
| `tt` | AM/PM | `PM` |

**Пример:** `"dd.MM.yyyy HH:mm:ss"` → `"15.02.2025 14:30:45"`

## 5. Счётчик

Возвращает последовательное целое число и сохраняет текущее состояние в **`RepoDict.IntDict`** по указанному ключу.

### Параметры

| Свойство | Тип | По умолчанию | Описание |
|---|---|---|---|
| **Ключ счётчика** | `string` | `"Counter"` | Ключ в `RepoDict.IntDict`. Разные ключи = разные счётчики |
| **Начальное значение** | `int` | `1` | Применяется **только** при первом вызове (ключ отсутствует в `RepoDict.IntDict`) |
| **Шаг** | `int` | `1` | Величина сдвига при каждом вызове. Может быть отрицательным |

### Логика работы

```
Вызов 1: RepoDict.IntDict["Invoice"] отсутствует
         → вернуть start(1001), записать 1002

Вызов 2: RepoDict.IntDict["Invoice"] = 1002
         → вернуть 1002, записать 1003

Вызов 3: RepoDict.IntDict["Invoice"] = 1003
         → вернуть 1003, записать 1004
```

### Независимые счётчики

Каждый ключ ведёт свой независимый счёт:

```
Ключ "Invoice"  | start=1001, step=1  → 1001, 1002, 1003...
Ключ "OrderNum" | start=10,   step=10 → 10, 20, 30...
Ключ "RowIndex" | start=0,    step=1  → 0, 1, 2...
```

### Сброс счётчика

Для сброса счётчика добавьте в начало процесса C#-выражение:

```csharp
// Полный сброс — при следующем вызове применится начальное значение
RepoDict.IntDict.Remove("Invoice");

// Установить произвольное значение
RepoDict.IntDict["Invoice"] = 500;

// Сброс всех счётчиков
RepoDict.IntDict.Clear();
```

> **Важно:** начальное значение применяется **только** когда ключ отсутствует в `RepoDict.IntDict`. Если ключ уже есть — начальное значение игнорируется, используется только шаг.

## 6. Хеш ID

Вычисляет SHA-256 хеш от входной строки. Детерминирован: одинаковый вход всегда даёт одинаковый результат.

### Параметры

| Свойство | Тип | Обязательно | Описание |
|---|---|---|---|
| **Входная строка** | `string` | **Да** | Строка для хеширования |
| **Префикс** | `string` | Нет | Добавляется перед хешем |

### Пример результата

```
Входная строка: "ИНН:7743013904 Дата:2025-02-15"
Префикс:        "DOC-"
Результат:      "DOC-a3f5b2c1d4e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2"
```

### Применение

- Уникальный ключ документа из известных данных (ИНН + дата)
- Проверка целостности строки
- Обфускация идентификаторов

## 7. Имя пользователя

Формирует email-адрес из имени, фамилии и домена.

### Параметры

| Свойство | Тип | По умолчанию | Описание |
|---|---|---|---|
| **Имя** | `string` | — | Имя пользователя (латиница или транслит) |
| **Фамилия** | `string` | — | Фамилия пользователя |
| **Домен** | `string` | `example.com` | Домен без символа `@` |

### Пример результата

```
Имя:     Ivan
Фамилия: Petrov
Домен:   company.ru
→ ivan.petrov@company.ru
```

> Всё приводится к нижнему регистру автоматически.

## 8. Шаблон

Заполняет строку-шаблон значениями из словаря `Dictionary<string, object>`.

### Параметры

| Свойство | Тип | Обязательно | Описание |
|---|---|---|---|
| **Шаблон** | `string` | **Да** | Строка с плейсхолдерами `{ключ}` |
| **Переменные** | `Dictionary<string, object>` | Нет | Словарь замен |

### Синтаксис плейсхолдеров

- Формат: `{имяКлюча}` — только буквы, цифры и `_`
- Нераспознанные плейсхолдеры остаются без изменений
- Значения преобразуются через `.ToString()`

### Пример

```
Шаблон:     "Уважаемый {name}! Ваш заказ №{orderId} принят {date}."
Переменные: { "name": "Иван Петров", "orderId": "ORD-12345", "date": "15.02.2025" }
Результат:  "Уважаемый Иван Петров! Ваш заказ №ORD-12345 принят 15.02.2025."
```

```
Шаблон:     "Файл: {dir}\{file}.{ext}"
Переменные: { "dir": "Reports", "file": "invoice", "ext": "xlsx" }
Результат:  "Файл: Reports\invoice.xlsx"
```

## 10. Валидация

| Режим | Обязательные поля |
|---|---|
| Все | **Результат** |
| `FileName` | **Базовое имя** |
| `HashId` | **Входная строка** |
| `Template` | **Шаблон** |
| `Timestamp` + `Custom` | **Кастомный формат** |

## Примеры использования

### Уникальное имя файла для отчёта

```
Тип:          FileName
Директория:   C:\Reports
Базовое имя:  report_{DateTime.Now:yyyyMMdd}
Расширение:   .xlsx
Результат:    C:\Reports\report_20250215(2).xlsx
```

### Номер счёта с префиксом

```
Тип:           Counter
Ключ:          "InvoiceNum"
Начало:        1001
Шаг:           1
→ Результат: "1001"

// Затем конкатенируем: "INV-" + результат = "INV-1001"
```

### Временная метка для имени файла

```
Тип:    Timestamp
Формат: yyyyMMdd_HHmmss
→ "20250215_143045"
```

### Хеш-ID для документа

```
Тип:           HashId
Входная строка: ИНН + "_" + дата
Префикс:       "DOC-"
→ "DOC-3a7f9c2b..."
```
