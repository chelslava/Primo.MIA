# Architecture Decision Records (ADR)

Этот каталог содержит Architecture Decision Records (ADR) - документы, описывающие важные архитектурные решения в Browser модуле.

---

## Что такое ADR?

ADR (Architecture Decision Record) - это документ, который фиксирует важное архитектурное решение вместе с его контекстом и последствиями.

### Структура ADR

Каждый ADR содержит:
- **Статус**: Принято / Отклонено / Устарело / Заменено
- **Контекст**: Какая проблема решается
- **Рассмотренные варианты**: Альтернативные подходы
- **Решение**: Выбранный подход
- **Последствия**: Положительные и отрицательные эффекты

---

## Список ADR

### [ADR-001: Использование RepoDict для хранения состояния сессий](ADR-001-RepoDict-Storage.md)

**Статус:** Принято  
**Дата:** 2026-03-10

**Проблема:** Необходимо хранить состояние сессий браузера между вызовами активностей в Primo Platform.

**Решение:** Использовать RepoDict - централизованное хранилище Primo Platform для хранения стека сессий.

**Ключевые моменты:**
- ThreadStatic и AsyncLocal не работают в Primo SDK
- RepoDict обеспечивает доступ из любой активности
- Поддержка сериализации и вложенных контейнеров

---

### [ADR-002: Ambient Context Pattern для SessionResolver](ADR-002-Ambient-Context-Pattern.md)

**Статус:** Принято  
**Дата:** 2026-03-10

**Проблема:** Как активности должны получать доступ к текущей сессии браузера?

**Решение:** Использовать паттерн Ambient Context через статический класс SessionResolver.

**Ключевые моменты:**
- Автоматическое разрешение sessionId
- Поддержка явного и неявного указания sessionId
- Минимальный boilerplate код
- Простота использования

---

### [ADR-003: Автоматическая очистка стека при входе в контейнер](ADR-003-Container-Stack-Clearing.md)

**Статус:** Принято  
**Дата:** 2026-03-10

**Проблема:** Что делать со стеком сессий при входе в контейнер (Sequence, If, While)?

**Решение:** Использовать флаг `isContainerEntry` в методе `Push`, который очищает стек при входе в новый контейнер.

**Ключевые моменты:**
- Изоляция контейнеров
- Предсказуемое поведение
- Гибкость для вложенных сессий
- Поддержка множественных сессий

                                    └─> Определяет поведение Push/Pop

## Когда создавать новый ADR?

Создавайте ADR когда:
- Принимаете важное архитектурное решение
- Выбираете между несколькими альтернативами
- Решение влияет на несколько компонентов
- Решение сложно изменить в будущем
- Нужно объяснить "почему" будущим разработчикам

**Не создавайте ADR для:**
- Мелких технических деталей
- Очевидных решений
- Временных workaround'ов
- Решений, которые легко изменить
